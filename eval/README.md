# eval/ — モーション評価用の素材置き場（git 同期しない）

VisionPose3D などの姿勢推定を検証するための動画を置く。**このフォルダの中身は
`.gitignore` で除外されていて、この README 以外は一切コミットされない。**

そうしている理由は容量ではなく**ライセンス**。評価に使いたい素材はたいてい
再配布できない（下の表）。「置いてはいけない場所に置いてしまう」事故を防ぐために、
評価素材はここに隔離する。`Assets/` は逆に**コミットされる**フォルダなので、
権利の確認が済んでいないものを置かないこと。

## 何を置いてよいか

| 出どころ | ここに置く | `Assets/` に置く（＝公開リポジトリに入る） |
|---|---|---|
| 自分で撮影したもの | ○ | ○（被写体の同意があれば） |
| AI生成（Firefly 等） | ○ | ○ |
| Pexels / Pixabay / Mixkit | ○ | **✗ 再配布禁止** |
| Wikimedia Commons の CC BY / CC0 | ○ | ○（`THIRD_PARTY_NOTICES.md` にクレジットが必要） |
| AIST Dance DB / MoVi / Human3.6M 等の研究用データセット | **✗** | **✗** |

最後の行が要注意で、3D正解付きのデータセットは軒並み「**学術研究限定・商用利用不可**」。
SYGNAL は法人なので、ローカル評価であっても使わない。

## 使い方

```bash
clang -fobjc-arc -framework Foundation -framework Vision -framework CoreGraphics \
      -framework AppKit -o /tmp/pose3d_eval tools/pose3d_eval.m
rm -rf /tmp/ev && mkdir -p /tmp/ev
ffmpeg -v error -i eval/<clip>.mp4 -vf fps=6 /tmp/ev/%04d.png
/tmp/pose3d_eval /tmp/ev/*.png
```

出るもの:

- **2D姿勢推定とのズレ（px）** — 関節ごと。3Dを画像に投影して、別モデルである
  `VNDetectHumanBodyPoseRequest` の位置と比べる。正解データが要らない相互チェック
- **幾何的な不変量（度）** — `torso_pitch` / `head_tilt` / `arm_elev_L,R` / `knee_flex_L,R`。
  これらは**正解が事前に分かる**（下記）ので、外れれば「間違っている」と言い切れる

## 比較用のベースライン（M2・1280x720・6fps サンプリング）

| クリップ | 2D比較の全関節平均 | 備考 |
|---|---|---|
| `Assets/sample_pose3d.mp4`（ダンス・前進/ターン/跳躍） | **21.3 px** | 正面・全身・好条件 |
| `Assets/sample_ballet.mp4`（その場・ゆっくり） | 21.6 px | 同上 |
| Wikimedia のバックスクワット | 34.6 px | 後ろ姿+バーベル遮蔽の難条件 |

関節別では **末端ほど誤差が大きい**（neck 13.6 → 足首 37 px）。新しいクリップが
21 px 前後なら「素直な条件」、35 px を超えるなら「推定が苦しい条件」と読む。

## 撮るなら（正解が分かるポーズを入れる）

三脚固定・全身が常に画面内・**各ポーズを1秒以上静止**。静止が要るのは解析が毎秒6〜9回
しかないためで、動き続けると誤差ではなく遅れを測ってしまう。

| ポーズ | 何の正解が分かるか |
|---|---|
| **T-pose** | `arm_elev_L/R` が **0°・左右一致**になるはず。最も価値が高い |
| **お辞儀（腰から90°）** | `torso_pitch` が 0→90° に振れるはず。奥行き推定の直球テスト |
| 首を左右に傾げる / うなずく | `head_tilt` だけが動き、`torso_pitch` は動かないはず |
| スクワット | `knee_flex` が 180→90° 付近まで |
| 腕をレンズに向ける | 2Dでは1点に潰れる。最も曖昧な条件 |
| 背中を向ける | 左右の取り違えが起きないか |

**首の左右回転（顔を横に向ける）は評価できない。** 頭の関節は `center_head` と
`top_head` の2点しかなく、この2点を結ぶ軸まわりの回転は原理的に表現されない。

## 既知の落とし穴

- **角度はカメラ空間で測る。** model 空間の +Y は体幹軸に沿っているので、
  そこで `torso_pitch` を測るとお辞儀でもほとんど動かない（スクワットで range 10.9° しか
  出ずに気づいた。カメラ空間なら 29.2°）
- **骨の長さは評価に使えない。** Vision は固定プロポーションの人体モデルの角度だけを
  推定しており、上腕 0.3165 / 前腕 0.2475 / 腿 0.4705 / 脛 0.4849 m は**別人・別動画でも同一**
- **メートル値は 1.8m 仮定でスケールされている**（`heightestimation` は TOP 入力では常に
  `reference`）。比・角度は信用してよいが、絶対距離は「1.8m 基準の単位」
